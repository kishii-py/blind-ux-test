# 客観複雑度計測 (4 層スタック)

「人間にとって直感的か」を **AI の賢さと無関係に**測るための計測仕様。
主用途は**修正前後の A/B 差分** (計測器は絶対値より差分に強い: AI の賢さは
両腕に等しく乗って相殺される)。

## 設計原理 (実験で確定)

- **完了バイアス**: AI ペルソナ (Sonnet 級) は賢すぎて完走する。実人間が「複雑すぎる」と
  評価したシステムでも全ゴールを達成した実測。→ **「達成」は直感性の証拠にならない**。
- **弱いモデルへの代替は不成立**: より小さいモデルで試したところ、vision = 知覚 (座標) の
  方が先に壊れて不正なショートカットへ逃げる / DOM 読取を許すと結局賢すぎる上に手抜きを
  過大申告する。**モデルを弱めても「人間にとっての複雑さ」は測れない**。
- **証拠の非対称性 (最重要ルール)**:

  | ペルソナの結果 | 証拠価値 |
  |---|---|
  | 賢い AI ですら詰まった・誤 turn した | **強い証拠** (賢い AI が誤る導線は人間は確実に誤る) |
  | 賢い AI が達成した | ほぼ無価値。**手数 (経路情報) だけ**を採用する |

- **役割分担**: AI ペルソナ = 計測器 + 経路サンプラー。主観「複雑すぎ」の最終権威 =
  実人間 (Layer 4 で較正)。

## Layer 1 — 構造カウント (完全に能力非依存)

最短エキスパート経路 (採取手順は後述) に沿って数える:

| 指標 | 数え方 |
|---|---|
| 画面・モーダル数 | ゴール完遂に通る別画面 / 別モーダルの種類数 |
| **文脈往復** | 一度離れた画面へ戻ってやり直す回数 (状態非保存による再入力もここで検出) |
| ナビ判断点 | 「次にどこを押すか」を選ぶ地点の数 |
| 必須入力 | 入力・選択の必須項目数 |
| **概念数** | ゴール完遂に理解が要る概念の数 (例: すべて vs フォルダ別 / 選択中バー / 外部公開) |
| **非自明な順序依存** | 「先に X しないと Y できない」が画面に示されていない箇所数 (**重い**) |
| 特殊 UI | native select / D&D / フォーカストラップ無しモーダル等、操作困難 UI の数 |

## Layer 2 — 人間コストモデル (HCI 標準手法の流用。トレースから決定論的に計算)

**人間に効いて AI に効かない負荷**を数値化する。テスターが誰でも同じ値になる:

| 指標 | 数え方 | 人間に効く理由 (AI には効かない) |
|---|---|---|
| **判断負荷** Σlog₂(Nᵢ+1) | 各判断点で画面内の可視インタラクティブ要素数 Nᵢ を機械カウント | 選択時間は選択肢数の対数に比例 (Hick の法則)。AI は 40 要素を一瞬で全部読む |
| **スメルギャップ** | 次に押すべきコントロールのラベルとゴール文の語彙を突合: 一致 / シノニム一致 / 不一致。**不一致ステップ数**を数える (何と何を突合したか必ず記録) | 人間はラベルの語彙一致で道を選ぶ (情報採餌理論)。AI はソフトウェア常識で補完してしまう |
| **記憶キャリー** | 画面をまたいで覚えておく値・状態の数 (件数を覚えて後で答える / 検索語の再入力 / 選択状態のリセット) | 人間のワーキングメモリは約 4 チャンク。AI は全履歴を完全記憶 |
| **fold 下率** | スクロールしないと次の正解コントロールが見えないステップ数 | 見えない物は押せない (AI と人間の数少ない共有弱点でもある) |
| **KLM 予測時間** | 簡易定数の合計: クリック 2.5s (判断 M + ポインティング P 込) / 入力 1.4s + 0.3s×文字数 / 画面遷移待ち 1.0s / スクロール 1.0s | 「初回予測 4.2 分 → 1.9 分」の対外説明力。**比較専用のモデル値** (絶対時間の予測ではない、と必ず注記) |

## Layer 3 — 経験的混乱サンプリング (ペルソナ実測の唯一の使い道)

| 指標 | 定義 |
|---|---|
| **経路ズレ** | ペルソナ実測手数 ÷ 最短手数 (体ごと + 中央値) |
| **junction 表** | 最短経路の各判断点 × 各ペルソナの初回選択 (正 / 誤 + 誤って何を押したか) |
| **誤 turn 収束** | 同一判断点で 2 体以上が誤った箇所数 = 賢さの交絡を越える強シグナル |
| **仮想ギブアップ** | 忍耐予算 = min(最短×2.5, 50 手) を置き、トレース上のどこで予算が尽きたか (「人間ならここで投げた」の推定地点) |

## Layer 4 — 実人間による較正 (ときどきでよい)

- 較正点の実例: 実人間「複雑すぎ」 ⇔ 往復 3・概念 ~11・順序依存 1 (重)・
  経路ズレ 3.2〜3.5x。
- **暫定閾値 (「要簡素化」バンド)**: 文脈往復 ≥2 / 経路ズレ ≥2.5x / 誤 turn 収束 ≥1 /
  重い順序依存 ≥1 のいずれか該当。
- 実人間の「複雑すぎ / 簡単」報告が入るたびにスコアと突合し、閾値を調整する
  (指標の妥当性はここで立つ)。

### ペルソナ自己申告の較正実績 (4 システム・機械計数との突合)

自己申告をどこまで信じてよいかの実測台帳。**原則 = 申告は参考値、正は機械計数と DB 裏取り**:

| 申告項目 | 信頼度 | 実測根拠 |
|---|---|---|
| goal 達成/未達 | **中** (過信あり) | 2 体が「達成」申告でキー不一致 (2 層工程の誤読 = 自信を持って間違えた)。一方で「確証が持てない」と不確実性を正直申告した体、「部分達成」を正確に自己判断した体もある — **表示が明快な画面ほど過信が起きる** |
| 手数 | 中 (集計粒度が腕ごとに揺れる) | スクショ枚数・ログ手順と概ね整合するが内訳明細は無いことが多い |
| 誤操作数 | **低め** | 申告 5 vs ログ明示 3。「探索の空振り」を含める / 含めないが腕により揺れる |
| 詰まり数 | 高 (定義が明確なため) | 「3 回失敗」定義はよく守られる。ただし「詰まり 0 なのに最大の詰まり記載あり」の併存は常態 (定義未達の最大摩擦を書く運用として解釈) |
| 原文引用 (見たもの/文言) | **高** | 全 wave で画面文言・数値の転記が DB / スクショと一致 (エラー原因の自力特定結果が DB と完全一致した例あり) |

## 最短エキスパート経路の採取手順 (オーケストレータ = 計測器側)

1. ペルソナと**同一ビルド**の環境で、オーケストレータ自身が snapshot 系ツールで
   ゴールを最短実走する (**計測器側なので snapshot / DOM 可** — ペルソナの vision 制約とは
   役割が違う)。
2. 各ステップで記録する: 画面名 / 操作 / 判断点なら可視インタラクティブ要素数 /
   正解コントロールのラベルとゴール語彙の一致度 / fold 内外 / 持ち越し状態。
3. 実行タイミング: 並列モード = 専用クローンで随時 / 直列モード = 全ペルソナ完了後
   (DB 状態を汚してよくなってから)。
4. Layer 1 + 2 はこのトレースから機械的に集計する。

## A/B モード (修正効果の定量証明)

1. **凍結する変数 (MUST)**: ゴール文 / 正解キーの採り方 / ペルソナ仕様 (人格・モデル・ツール) /
   開始 URL / 環境構築手順。**変えてよいのは対象コードだけ**。
2. baseline (修正前ビルド) と treatment (修正後ビルド) で同一計測を行い、
   **全層の before/after 差分表**を作る。
3. 差分表には**質的な 1 行**を必ず添える: 「危険な結末が除去されたか」
   (例: 移動未完のまま放置 → 1 アクションで完遂)。
4. ペルソナ数は各腕 1〜2 体で足りる (主役は Layer 1+2 の構造差分。ペルソナは
   誤 turn 消滅の確認役)。
5. 実証済みの原型 (一括移動機能の改修): 文脈往復 3→1 / 順序依存 1→0 /
   native select 必須→迂回 / 最短 ~20→~13 手。

> **A/B で計測器そのものを改善しないこと**: ペルソナの契約ファイルを改善したくなったら、
> 比較用に**改訂前のバイト同一コピーを凍結**して残す。計測器が変わると前後比較が無効になる。
