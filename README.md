# Blind UX Test

**説明書を渡さずに新人へ仕事を頼んで、どこでつまずくかを横で見る。** それを AI にやらせます。

社内システムや業務アプリは「初めて使う人」を集めるのが大変です。かといって作った本人は
仕組みを知りすぎていて、使いにくさに気づけません。そこで AI に**仕事の目的だけ**を伝えて
実際に画面を触らせ、詰まった場所を記録します。

---

## 使い方

Claude Code にこう言うだけです。

```
http://localhost:8000/ の受注登録画面を初見テストして
```

あとは AI が全部やります。

```
  あなた
    │  「初見で使える？」と頼む
    ▼
  AI（オーケストレータ）
    │  ① 対象システムを調べる
    │  ② 仕事の頼み方（シナリオ）を作る
    │  ③ 環境を整える
    │  ④ 何も知らない AI を起動する ──┐
    │                                  │  画面を撮る・クリックする
    │  ⑤ ログを読んで答え合わせ  ←────┘
    │  ⑥ レポートにする
    ▼
  あなた（レポートを読む）
```

**人間がやるのは、最初の一言と、出てきたレポートを読むことだけです。**

```bash

cp -r blind-ux-test ~/.claude/skills/
cp blind-ux-test/agents/ux-blind-tester.md ~/.claude/agents/
```

playwright MCP も必要です。

```jsonc
// ~/.claude.json の mcpServers
"playwright": {
  "type": "stdio",
  "command": "npx",

```

ブラウザ本体も入れてください（`npx playwright install chrome`）。動作確認は macOS のみです。

## なぜ難しいのか

AI にテストさせると、**賢すぎて全部できてしまいます**。人間が「複雑すぎる」と評価した
システムでも、AI は全部のゴールを達成しました。つまり **「AI ができた ＝ 使いやすい」とは
言えない**ということです。

では弱い AI を使えば人間に近づくかというと、それも違いました。弱くすると画面を正しく
見ること自体ができなくなり、人間とは別の失敗をします。**AI を弱めても人間のつらさは
測れません。**

## どう解いたか

### 1. 失敗だけを信じる

| AI の結果 | 扱い |
|---|---|
| 賢い AI でも詰まった | **強い証拠**。人間なら確実に詰まる |
| 賢い AI ができた | ほぼ参考にしない。手数だけ見る |

成功を信じず失敗だけを信じれば、「AI が賢すぎる」問題を避けられます。

### 2. AI には効かない負担を測る

**人間だけがつらくて、AI は平気なこと**を数えます。

- 画面にボタンが 40 個ある → 人間は迷う。**AI は一瞬で全部読む**
- 前の画面の数字を覚えて次で使う → 人間は忘れる。**AI は完全に記憶している**
- ボタンの名前が目的の言葉と違う → 人間は見つけられない。**AI は察してしまう**

これなら AI の賢さに関係なく、人間にとっての難しさを測れます。

### 3. 「見ないで」ではなく「見られなくする」

お願いしても、AI は必要になれば見ます。だから**道具ごと取り上げます**。
ページの中身を読む道具も、コマンドを打つ道具も、最初から持たせません。
渡すのは「画面を撮る」「クリックする」「文字を打つ」だけです。

ただし**完全ではありません**。自分の撮った画像を見るために画像を読む道具は残るので、
その使い方だけはルールで縛っています。

## 実際に見つかったもの

7 つの業務システムに対して延べ 45 回ほど走らせた結果、**詰まる場所は驚くほど同じ**でした。

- **削除の確認に名前がない** — 「本当に削除しますか？」だけでは、自分がどれを消そうと
  しているか確認できない。確認画面に対象の名前を入れたところ、**直したことを知らない
  AI が 3 つのシステムで続けて「前の職場のシステムより安心できる」と評価**した
- **エラーが理由しか言わない** — 「注文番号が重複しています」だけでは、どれと重複したのか
  分からない。重複相手と直し方を書き足したら、**原因を突き止めるまでの操作が 77 手 → 43 手**に
  減った。しかも AI が 77 手かけて自力で調べ上げた内容は、データベースの中身と完全に
  一致していた（＝**システムが最初から出せる情報を、人が手作業で組み立てていた**）
- **登録した番号で後から探せない** — 一覧に番号の列がないと、今登録したものを見つけられない
- **一覧の行をクリックしても詳細に飛ばない** — 同じ部品を使っていても、この配線があるか
  ないかで**初めての人がたどり着くまでの手数が 3〜5 倍**変わった

どれも「言われてみれば当たり前」ですが、**作った人には見えません**。

## 動作確認した範囲

この中身は 7 システム・45 走行の実運用から抜き出したものですが、
**この配布物の形で通したのは下の 2 つだけ**です。

| | 状態 |
|---|---|
| 1 体だけ走らせる | ✅ 2 回検証（答えもデータベースの中身も一致） |
| 道具の取り上げ | ✅ 検証（穴を 1 つ見つけて塞いだ） |
| 複数体を同時に走らせる | ⚠️ 実運用の手順だが、この配布物では未検証 |
| A/B・マニュアル監査モード | ⚠️ 同上。**測り方は読み物として扱ってください** |
| macOS 以外 / Django 以外 | ⚠️ 未検証 |
